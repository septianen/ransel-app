# Contract changes

Every change to `shared/` gets a line here, newest first. Format:
`YYYY-MM-DD · agent · additive|breaking · what · why`

- 2026-10-16 · backend · additive (behaviour) · `RecommendationItem.rating` is now always null (KDoc only; the field stays so nothing breaks) · Google's rating and priceLevel are Enterprise-tier Place Details fields (1,000 free a month, $20 per 1,000), too expensive per search. **Frontend:** do not show a rating on swipe cards; remove it from the design when convenient. The price filter now uses the LLM's cost estimate against the destination price guide, so `priceLevel` from Google is not used either.
- 2026-10-16 · backend · breaking (owner approved: SEN's `docs/specs/AI-Recommendation-Spec.md`) · `BudgetLevel` replaced by `PriceLevel { LOW, MEDIUM, HIGH }`; `Interest` loses BEACH and gains RELAX; `RecommendationRequest` loses `destination`/`startDate`/`endDate`/`budget` (they come from the trip) and gains `priceLevel`, `focusArea`, `extraInterests`; new `ExploreSuggestionsResponse` and `ApiRoutes.EXPLORE_SUGGESTIONS` (`GET /explore/suggestions`) · Explore is chosen per trip, price level is relative to local prices, destination interests come from the AI. `ErrorCode.RATE_LIMITED` (already there) is used for the suggestions soft limit. **Frontend:** `:composeApp` does not compile until `ExploreSession`, `ExploreViewModel`, `ExploreScreen` and `SwipeScreen` (and their strings) stop using `BudgetLevel`/`Interest.BEACH`/the removed request fields; follow the spec's User flow and Form inputs. New validation codes under 422: `tripId = TRIP_ENDED`, `interests = EMPTY`, `extraInterests = TOO_MANY`.
- 2026-10-16 · backend · additive · `ApiRoutes.placePhoto(placeId)` (`GET /places/photo/{placeId}?exp=&sig=`, signed, no bearer, 404 when no photo) and `RecommendationItem.photoAttribution` (top cards only); `photoUrl` is now filled with the signed path relative to `ApiRoutes.BASE` · Explore cards show Google photos without the Places key reaching the app (B5.7). **Frontend:** F5.6 can start; resolve `photoUrl` against `apiOrigin()` + `ApiRoutes.BASE`, load it without the Authorization header, and show `photoAttribution` (or "Foto: Google").
- 2026-10-15 · backend · breaking (owner approved) · `inviteUrl(code)` now returns `https://ransel.mietek.tech/j/<code>` (was `https://ransel.app/j/<code>`); `InviteDto.url` follows `APP_BASE_URL` on the server · the product owner chose `ransel.mietek.tech` as the invite-link domain. **Frontend:** change the App Links host in `AndroidManifest.xml` (`android:host`), the host check in `InviteLinks.parseInviteCode` and its tests, the iOS Associated Domains entry (`applinks:ransel.mietek.tech`), and `docs/specs/app-links.md`; the web app already receives `/j/<code>` on its own origin.
- 2026-10-15 · backend · additive · `ErrorCode.RATE_LIMITED` (429) · login/register are rate limited per client address (B3.1); `AI_QUOTA_EXCEEDED` stays for the Explore daily quota only. **Frontend:** show a generic "too many attempts, try again in a minute" message and honor the `Retry-After` header.
- 2026-10-14 · frontend · additive (loosens validation) · `domain/Itinerary.kt`: `activityDurationMinutes`, `endsNextDay`; `itinerary_items.endTime` may now be earlier than `startTime`, meaning the activity ends the next day (belongs to `dayDate`, the day it starts; equal = 0; always < 24 h). `reorder` and `scheduleAtEndOfDay` use the wrap-aware duration, starts stay clamped to 23:59 · overnight activities ("Otw ke Bali" 23:00–01:00). **Backend:** relax `itinerary_time_range` (`end_time >= start_time`) in `V1__init.sql` (editable in place before the first deploy) and drop any `endTime >= startTime` request validation; use `activityDurationMinutes` for durations.
- 2026-10-14 · frontend · additive · `domain/TripDates.kt`: `itemsOutsideRange`, `ItineraryItemDto.toUnscheduledInput()` · shortening a trip's dates moves activities on removed days to "Belum dijadwalkan" instead of deleting them (Edit trip design). Backend: apply the same in `PUT /trips/{id}` (B2.4) and in sync.
- 2026-10-14 · frontend · additive · `domain/ExpenseSummary.kt`: `summarizeExpenses(baseCurrency, budgetMinor, expenses, timeZone)` returning `ExpenseSummaryDto` · the app computes the Expenses summary locally (Phase 1) and the server (B2.7) must give the same numbers, so the rule lives in `shared`. Backend: use it for `GET /trips/{id}/expenses/summary` instead of re-implementing.
- 2026-10-14 · setup · initial · ApiRoutes, DTOs, enums, ErrorCode, Timestamp serializer, domain (reorder, scheduleAtEndOfDay, splitEqually, computeBalances, fewestTransfers, convertMinor, checkPassword, generateInviteCode) with tests · handoff package from the design phase. Endpoints added on top of the original TRD table: DELETE packing item, PUT/DELETE expense, POST /auth/logout, GET invites, GET settlements, DELETE recommendation feedback (undo). `RecommendationRequest.newSearch=false` (background next batch) does not count against the daily quota.
