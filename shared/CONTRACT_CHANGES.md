# Contract changes

Every change to `shared/` gets a line here, newest first. Format:
`YYYY-MM-DD · agent · additive|breaking · what · why`

- 2026-10-25 · frontend · breaking (owner approved 25 Oct, option A) · Group foundation, stage 1: people in a trip are trip members with their own id and no account is needed. `userId` becomes `memberId` in `ExpenseDto.paidByMemberId`, `ExpenseInput.paidByMemberId`, `ExpensePayerDto`, `ExpenseSplitDto`, `MemberBalanceDto`, `TransferDto`, `SettlementDto`, `CreateSettlementRequest` and the `domain/SplitBill.kt` types; `ApiRoutes.member(tripId, memberId)` now takes a member id; `TripMemberDto` gains `memberId`, `userId` becomes nullable, plus `phone` (OWNER only) and `claimedAt`. Additive: `domain/MemberIds.kt` `memberIdFor(tripId, userId)` (the id of an account's own member row, so the app can write it offline), `domain/Members.kt` (`validateMemberName`, `normalizePhone`, `whatsappLink`, `extractMentions`, `memberInitials`), `AddMemberRequest`, `POST members`, `memberClaim` (POST claim, DELETE undo), `dto/CommentDtos.kt` and routes `comments`, `commentCounts`, `comment`, enum `CommentTarget`, `NotificationType.MEMBER_CLAIMED` and `COMMENT_MENTION`, `ErrorCode.MEMBER_ALREADY_CLAIMED` and `MEMBER_HAS_ACCOUNT`, `GET /invites/{code}` is public and `InvitePreviewDto` gains `memberInitials`, `guestNames`, `activityCount`, `baseCurrency`, `sharedSpendMinor` · a group trip where not everyone has an account or the app (PRD 24 Oct 2026, TRD "Group trip features"). Migration V15 (V1-V4 are live, so TRD's "fold into V3" is not possible). **Backend:** V15 backfills `trip_members.id = memberIdFor(trip, user)` and rewrites the money tables; claim moves rows in one transaction and logs them so the OWNER can undo. **Frontend:** a local expense of a signed-in user uses `memberIdFor(tripId, userId)`; guest data uses `memberIdFor(tripId, LOCAL_USER_ID)` and is rewritten at sign-in; Room v5; comments are online only (not in /sync).
- 2026-10-24 · frontend · additive · `ApiRoutes.roundClose` (`POST /trips/{id}/rounds/{roundId}/close` → 204, OWNER only): ends voting early by setting `closesAt` to now, so `RoundSummaryDto`/`RoundDto` need no new field (state becomes CLOSED); 409 `VOTING_CLOSED` when already closed, 409 `ROUND_ALREADY_DECIDED` when decided · the owner may close a voting before its 24 h end. Also server config only: undecided rounds now expire 3 days after creation (was 7). **Backend:** implement the endpoint and set the `ROUND_EXPIRY_DAYS` default to 3.
- 2026-10-23 · frontend · breaking (owner approved 23 Oct: old builds are not in use) · `RecommendationRequest.focusArea` removed, `RecommendationRequest.destination: String? = null` added (at most 200, 422 `destination = TOO_LONG`); `GET /explore/suggestions` accepts `destination` together with `tripId` · an existing trip's Explore form now has a "Destinasi" field prefilled from the trip that the user can change (a Yogyakarta trip extended to Solo): the "Khas …" chips and the search follow it, while dates, budget and members still come from the trip and the trip itself is not changed. **Backend:** use `body.destination ?: trip.destination` for the prompt, Places bias, price guide and cache key; drop the focus-area prompt line, `findPlaceId`'s focusArea and `MAX_FOCUS_AREA`; with `tripId` + `destination` the suggestions use that destination and the trip's month and budget.
- 2026-10-22 · backend · additive · Karung "Tambah pengguna": `POST AdminRoutes.USERS` with `CreateUserRequest(email, displayName)` → 201 `AdminUserDto`, `AdminAction.USER_CREATE` · the owner adds accounts from the admin app instead of `SEED_USERS`; the server sends an invite email ("Atur password", 7-day link through the existing `/reset-password` flow). **Frontend:** `adminApp` gets the button + dialog (F9.9), shown only when `AdminMeDto.passwordResetEmailEnabled`; errors `INVALID_EMAIL`, `REQUIRED`, `EMAIL_ALREADY_REGISTERED`. Traveller apps: nothing to change.
- 2026-10-22 · backend · additive · Email verification (owner approved 22 Oct, option "use the app, Explore waits"): `MeDto.emailVerified` (default true), `VerifyEmailRequest`, `VerifyEmailResponse(email, creditsGranted)`, routes `AUTH_EMAIL_VERIFY` (public) and `AUTH_EMAIL_RESEND` (bearer), `ErrorCode.VERIFY_TOKEN_INVALID` (400) and `EMAIL_NOT_VERIFIED` (403) · sign-up opens to everyone, and the 30 signup credits must not be farmable with made-up addresses. Register still answers 201 with a session; the server emails a link `APP_BASE_URL/verify-email?token=` (24 h, a resend voids older links). Until verified: `POST /recommendations`, `GET /explore/suggestions` and `POST /credits/redeem` answer 403 `EMAIL_NOT_VERIFIED`, the wallet holds no signup grant; the grant arrives on verification. Existing accounts are marked verified by the migration. **Frontend:** after sign-up show `VerifyEmailScreen`; handle `/verify-email?token=` (web route; Android App Link) with `EmailVerifiedScreen` / its invalid-link state; in Explore, when `me.emailVerified` is false, show the verify gate (resend + "Sudah verifikasi" = refetch `/me`); map `EMAIL_NOT_VERIFIED` to the same gate. Design: `docs/design/README.md` (VerifikasiEmail, EmailTerverifikasi, VerifikasiTidakBerlaku, JelajahBelumVerifikasi).
- 2026-10-21 · backend · additive · Admin app stage A (docs/specs/admin-spec.md, approved by the owner 21 Oct): `api/AdminRoutes.kt` (`/admin/me`, users list/export/detail, credit ledger, adjust credits, sign-out-all, disable/enable, password reset, audit), `dto/AdminDtos.kt` (`AdminMeDto`, `AdminUserDto`, `AdminUserDetailDto`, `AdminTripDto`, `AdminDeviceDto`, `AdjustCreditsRequest`, `AdminActionResult`, `AdminAuditEntryDto`), enums `CreditDirection`, `UserStatus`, `AdminAction`, `ErrorCode.ACCOUNT_DISABLED` (403), optional `CreditLedgerEntryDto.note` and `balanceAfter` (admin responses only), KDoc: an `ADJUSTMENT` ledger row may be negative · Karung lets an admin add or subtract a user's credits and deactivate accounts. **Frontend:** `adminApp/` uses these (F9.1–F9.3). - 2026-10-21 · backend · additive · Itinerary voting (docs/specs/voting-spec.md, approved by the owner 21 Oct): `dto/VotingDtos.kt` (`RoundSummaryDto`, `RoundDto`, `RoundPlaceDto`, `TallyDto`, `VoterDto`, `VoteRequest`, `DecideRequest`), enum `Vote`, routes `rounds`, `round`, `roundVote`, `roundDecide`, `ErrorCode.ROUND_NOT_FOUND`, `VOTING_CLOSED`, `ROUND_ALREADY_DECIDED`, `ROUND_LIMIT`, optional `RecommendationRequest.roundId` and `RecommendationResponse.roundId`, `domain/Voting.kt` (`roundState`, `hoursLeft`, `firstUnvotedIndex`, `sortByLikes`, `VoteStage`), `VOTE_*` notification params in the `NotificationDtos` KDoc · on a trip with 2+ members an AI search becomes a round that every member votes on and the OWNER decides. **Frontend:** when `roundId` is set, swipes call PUT/DELETE votes (no itinerary item, no feedback); next batches send `roundId`; the OWNER's decide creates the itinerary items through the normal path first, then calls decide; render VOTE_* by `stage`. - 2026-10-22 · backend · additive · Notifications: `dto/NotificationDtos.kt` (`NotificationDto`, `NotificationsDto`, `RegisterDeviceRequest`, `MarkReadRequest`, `NotificationSettingsDto`, `UpdateNotificationSettingsRequest`), enums `NotificationType` and `DevicePlatform`, routes `DEVICES`, `NOTIFICATIONS`, `NOTIFICATIONS_READ`, `NOTIFICATION_SETTINGS` · push (FCM) and an in-app inbox for joins, shared expenses, settlements and packing/activity reminders (voting types are reserved).
